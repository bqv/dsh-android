# DSH for Android v0.6.4

Automations changed underneath the app, and the app learned to manage them. Undo came to
the composer. A password field stopped lying to your keyboard.

## Automations were replaced, and the app was quietly wrong

The host's automation plugin was not renamed. `@michengai/dsh-automation` was **rejected as
incompatible** with dsh 0.2.0-rc.2 and replaced by the official Schedule bundle. The old
plugin gave every run its own throwaway session named `dsh-automation-session-…`; the new one
stores a task against the **original session** and delivers each occurrence into it as an
ordinary turn.

The app identified automation sessions **by that id prefix**. After the swap it matched **0 of
485 sessions** — and nothing failed. The landing filter, the drawer section and the idle-alert
mute simply stopped applying, and the bug they were written for came back looking new.

Sessions are now identified from the host's own `schedule/catalog` — the same snapshot the web
client marks rows from. The session keeps its Workspace and gains a clock mark instead of being
lifted into a synthetic section, because a session a schedule delivers into is now a **standing**
session rather than a disposable artefact: preferred against when choosing what a fresh open
lands on, never hidden, and still the fallback when nothing else has content.

Keying on the host's `[task] …` titles was considered and rejected — those are a human naming
convention, not something the subsystem provides. And because an indicator that goes quiet
should say why, a lost schedule signal logs under `DshSchedule`: the first loss of an episode,
then silence until a read succeeds.

## Managing schedules

There is now an **Automation tasks** surface in the drawer footer: every schedule on the host,
what it does, the session it delivers into, whether it is active, and when it last delivered.
The timing uses the web's own vocabulary — *Every 30 minutes*, *Daily at 00:45 (UTC)*,
*Weekly on Mon, Wed at 09:00* — with the zone named only when it differs from the device's, and
**always** named in the detail. Cron expressions are printed verbatim rather than re-described,
because a second implementation of the host's parser is a second place to be wrong.

Deleting is behind a dialog that names the task and says what goes (the task and its delivery
records) and what does not (the session, its messages, its queue).

Two things were deliberately **not** built, because the host does not offer them to a client
rather than because they were overlooked:

- **No enable/disable.** `schedule/update` has no `status` member, and it *refuses* an inactive
  row, so a toggle could neither disable nor re-enable anything. Status is host-owned. Delete is
  the only stop available from the app.
- **No create.** Creation is an agent tool bound to the agent's own session, not a remote. The
  web's own New button starts a session so an agent can be asked, and the sheet says the same.
  Every wall-clock kind also requires an explicit time zone, with no default to guess at.

## Undo in the composer

Compose moved to BOM 2024.09.00 for `TextFieldState`, which carries an undo history the old
`TextFieldValue` never had. One control beside `+`: tap to undo, long-press to redo, enabled
only when there is something to undo, and it never moves the row. Hardware `Ctrl+Z`,
`Ctrl+Shift+Z` and `Ctrl+Y` work too.

Two behaviours worth knowing. A sent message **cannot** come back on undo — the send-clear and
a `/` pick are programmatic edits, and `TextFieldState` clears the history it found when one
happens, so no revived draft can be sent twice. And the restore-on-failure path now keys on
`armedBySend && !undoneSinceSend && empty`: undo-to-empty no longer refills the box with the
text you just undid.

## The login screen could corrupt your password

The password field was masked but told the IME it was **ordinary prose** — no keyboard type, and
Compose's default `autoCorrect = true` — so suggestions and autocorrection were live inside the
dots. An autocorrected password silently becomes a different password, and the account locks out.

It now declares `KeyboardType.Password`, `KeyboardCapitalization.None` and `autoCorrect = false`,
the account field gets the same treatment for capitals and autocorrect, `Done` submits (it used
to only hide the keyboard), and a **reveal toggle** sits in a fixed slot so you can read what you
typed before pressing anything. A synchronous latch means one gesture cannot send two sign-in
requests — the thing that turns one mistake into a lockout.

## The sidebar told you nothing, in colour

Some Workspace titles were dimmed, and nobody could say why. The rule was `Unknown`: the host's
registry named a member the client's roster had never delivered — undecidable from the screen,
and for a group that draws rows it was the *only* signal.

The third run state is gone. The title is now blue when something visible is running and
ordinary otherwise, which is a legend you can confirm by looking at the rows. Incomplete
membership became a **number** in the count column — `2 of 13` — where a count belongs, visible
either folded or open.

The cause was residue: ~70 ids from the retired automation plugin, still listed as Workspace
members by the host's registry while their transcripts are gone. The host can prune them; the
app now renders honestly whether or not it does. And the warning that reported this had been
repeating all seventy ids on every roster pull — 295 identical lines in one buffer — so it is
latched, and now logs a count.

## Notes

994 tests across 107 suites. Three things in this release were found by reading the host's own
source rather than by reasoning about it: that `schedule/update` cannot toggle status, that
creation is an agent tool and not a remote, and that the web's countdown has **no** one-minute
floor — a rule this release's author had invented and then seen written into a test. The app
mirrors the web; the web is the authority.
