# DSH for Android v0.6.6

Workspaces can be dragged into order, the drawer gains the web's Workspace Tree, and two state
bugs that made the app lie about itself are fixed.

## Reorder Workspaces by dragging

Long-press a Workspace header and drag. The section lifts, the list reorders live under the
finger, and an accent line marks where it will land. Release commits; dragging outside the drawer
or pressing Back cancels without sending anything.

The order is the host's, not a local preference: the move goes out as `workspace/insertBefore`,
the reply's complete order replaces the list, and a refusal **snaps back** with the host's own
reason rather than leaving an order the server does not hold.

The web reorders Workspaces with HTML5 drag, which produces no events on touch — so a gesture is
a deliberate divergence, not a port. Screen readers cannot drag, so each header also carries
"Move up" and "Move down" as accessibility actions; there is no visible menu.

Tree mode nests by path, so a drag reorders **siblings only**. It cannot re-parent anything.

## Workspace Tree

A third grouping beside WorkSpace and List, mirroring the web: each Workspace nests under its
**nearest registered ancestor directory**. Nested headers indent 12 dp per level, child Workspaces
come before a parent's own sessions, folding an ancestor hides its children, and the collapse
state is shared with WorkSpace mode — as the web shares it.

The rule that matters is path-based, not string-based: `/work/apple` does not nest under
`/work/app`, and an unregistered intermediate directory is skipped. On this box that produces a
real three-level hierarchy, because `/home/user/var/work` is not itself registered.

## Skip now sends a skip

Declining a question sent `{"kind":"next"}`. The host accepted it — and read it as *"this client
declines, ask the next answerer"*. With the phone as the only answerer that became `NO_PROVIDER`,
which the ask does **not** fail fast on: it waited out the tool's full timeout and then reported
*pending*. So skip looked broken because it was, in the worst way: accepted, logged nothing, and
meant something else.

It now sends what the web sends and what the host's own tool copy describes as "the user
explicitly skipped this question": a `result` batch with an empty `selected` list per question.

A refused skip now **keeps the card**, says why in red, and re-arms so it can be tried again —
instead of clearing optimistically.

## Close, Restart connection, Force quit

**Exit is now Close.** It only ever finished the Activity. The connection and the notification
service stay alive on purpose, so an agent that needs a human still reaches the phone with the UI
gone. The label promised otherwise.

**Restart connection** rebuilds the transport in-process: the multiplexer and its socket, every
route fault and hold, the cached winner, the probe cooldowns, OkHttp's shared connection pool and
dispatcher, and the client's own route-refresh scope. A probe already in flight can no longer
complete after the reset and write a winner. What it keeps is deliberate: cookies, config, drafts,
staged attachments, and the attention centre's pending cards.

**Force quit** ends the process. It exists because some wedges are below anything the app can
reach — the platform DNS cache, a native socket, host-side state. Three verbs, three meanings, and
the confirmation names all three.

## The roster can no longer freeze silently

Three separate faults could leave the drawer stuck, and one malformed answer could empty it:

- A `pendingRefresh` boolean was set before a debounce and cleared after it; a cancelled coroutine
  left it set and **every later refresh returned early, forever**. It is a job handle now.
- The resume path returned before the pull. Reconnecting a *subscription* never re-pulled a
  *list*, so sessions created while the phone was pocketed never appeared.
- Six call sites discarded every non-auth failure with no log and no UI. One sink now logs,
  publishes an error, and **keeps the rows**, and the drawer says the list below is the last one
  that loaded.
- `items` missing or malformed became a **confident empty roster**. It is refused now; `[]` is
  still accepted as genuinely empty.

## A failed send hands the text back

Sending into an existing session skipped the restore whatever failed, because the flag governing
it was only set for the first send off the pending seat. The flag is gone; the failure path is one
sink. A 504 no longer pastes the web server's HTML — it says the host did not answer and its web
server replied instead, and adds that your message is back only when it actually is.

One caveat worth knowing: a 504 proves the *reply* was lost, not that the prompt was not accepted.
Re-sending can duplicate a delivered message.

## Notes

1116 tests across 127 suites. Three of the bugs here were the same shape — a state the app
asserted without having earned it: an empty roster from an unreadable answer, a cleared card for an
unaccepted skip, and a question declined by asking for another answerer. Each now either reports
what it does not know or refuses to claim it.
