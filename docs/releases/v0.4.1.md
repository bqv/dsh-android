# DSH for Android v0.4.1

A small one: the jobs sheet stops hiding the thing it exists to show.

## A job's command is no longer clipped after `cd`

The row capped its label at two lines, which is enough to read `cd /some/long/path &&`
and no further — the part of a command that says the least about what it does. It wraps
now, and a command with backslash continuations reads as the shell wrote it.

That row is also the only place a command appears: the compact seat beside the
transcript is one line by design, so nothing else was carrying it.

## One "Show more" per job, covering the command and the detail

Neither is bounded in practice. The detail can be a paragraph, and a command can be a
`python3 - <<'EOF'` heredoc that runs most of the way down the sheet — which a screenshot
settled, after this was written on the guess that commands are "a line or three".

So both are shown to four lines with a single offer beneath them. One toggle rather than
two: one under the command and one under the detail would read as two different things to
expand, when what you want is the rest of *this job*.

The offer appears only when something is actually hidden, read from the text layout's own
overflow rather than guessed from a character count — a count cannot know how wide the
sheet is on a given phone, and would either offer a "Show more" that reveals nothing or
hide one that was needed. It also had no touch target worth the name at first: a bare line
of `micro` text is about 15dp tall, so the padding is inside the clickable now.

## What is not verified

- **The offer's condition.** The JVM harness lays text out with stub metrics — probed
  directly, 24,892 characters measure as a single 260px line, about 0.6px per glyph — so
  nothing wraps, nothing overflows, and `hasVisualOverflow` is false however long the
  string is. No test in this repository can see where text breaks; that one has to be
  seen on a device. `TextOverflowProbeTest` records the limit so the next attempt does not
  spend the same hour on it.
- The drawer's restore waiting for a finger to lift, and the bash wrap's cost profile,
  remain as they were in v0.4.0: reasoned from the recorder, not confirmed by eye.
