# DSH for Android v0.2.0

> **Corrected in v0.2.1.** The **Ctrl-C and Ctrl-D work** bullet below was wrong
> for this release: a soft keyboard's own Ctrl key did not work — it typed a
> literal `c` or `d`. Only the panel's own Ctrl cap did. See
> [v0.2.1](v0.2.1.md).

A native Android client for DeepSeek Harness. No WebView anywhere in it: the transcript,
the drawer, the composer and the terminal are Compose and Canvas over the host's own
Remote API.

## The Shell tab

A third view beside Chat and Trajectory: a real PTY over the host's `terminal` Remote
namespace, with two seats labelled by the policy actually in force.

- **Host shell · Full access** (the default) is an unconfined shell: a dedicated session
  per workspace — or rooted at the session's own cwd when it is in no workspace — given
  `danger-full-access` *before* any terminal exists in it, then archived so it stays out
  of the drawer. This is the seat where `htop` shows the host's real processes.
- **This session · Workspace Write / Read Only** is the session's own terminal, confined
  by that session's policy. A terminal inherits its session's sandbox with no per-terminal
  override, which is exactly why the second seat exists.
- The grid is one `Canvas` with a block cursor over a hand-written, Android-free VT
  emulator: incremental UTF-8 across chunk boundaries, cursor addressing, erase/insert/
  delete, DECSTBM scroll regions, the `?1049` alternate screen with save/restore,
  16/256/truecolour SGR, the ACS line-drawing table, and DSR/DA answers written back.
- A key row carries the keys a soft keyboard cannot produce — `Esc`, `Tab`, `^C`, `^D`,
  `Ctrl`, arrows, `PgUp`/`PgDn`, `Home`/`End` — and keystrokes reach the PTY through the
  app's own input connection, so an IME cannot autocorrect what you typed.

## Fixed since v0.1.0

- **The transcript no longer rewrites itself under a reader.** A turn folding used to
  replace 79% of the visible rows in a single step, taking a parked reader to the start of
  the session. The fold is now held while the reader is off the end: **0% churn**, against
  60–62% in a reverted control build, so the measurement can fail.
- **Typing in the Shell tab is exact.** A fast burst used to arrive as `aabcdefgh` and
  autocorrect rewrote `vim` into `vI'm`; keystrokes now come from the input connection.
- **Ctrl-C and Ctrl-D work** from a soft keyboard's own Ctrl key — Android reports no
  character for a Ctrl chord, and the old handler read the character.
- **A new session is created when you first use it, not when you open the hero.** Leaving
  the new-session screen no longer costs a row: picking a workspace, or a permission or
  preset, leaves nothing behind until you send, and a send that cannot reach the host hands
  the draft back instead of keeping a half-made session.
- **The background-jobs seat reads the session in front of you**, not the last one that
  reported: a job settling in another session can no longer put its "done" dot on yours.
- **The drawer** dismisses on a tap outside it again, per-workspace collapse survives a
  restart, a pending question outranks "running" on the status dot, a name you set on
  purpose beats a blank placeholder, and the hole above "Search sessions…" is gone.
- **The composer**: the send button meets the card's curved edge, the statistics row is one
  line pinned to both ends, and the queue dock's corner gaps are closed — measured
  fill-to-fill where background used to show.
- **A slow or unreachable host** reads as what it is: a named loading state and a
  "Reconnecting" chip instead of a blank new-session screen.

## Under the hood

- **230 JVM tests** — the VT core, the terminal's attachment and sequencing gates, the seat
  resolution, the session-target rules and the key tables are pure Kotlin so they can run
  on a runner. CI now runs them **before** it builds the APK.
- The device plumbing (adb discovery, the wireless lease) moved out of this checkout into
  the author's host tooling.

## Known gaps

- In the terminal: scrollback is retained but not drawn, no mouse reporting, no terminal
  search, one terminal on screen at a time, no sixel/kitty graphics, no OSC 8 hyperlinks,
  no bracketed paste, no IME composition regions.
- Two cosmetic terminal gaps are known and deliberately deferred to the next round: **the
  font is not final**, and **a selected row's highlight sits slightly off-centre**.
- **Re-attach after a network drop is unverified** — the emulator's `svc wifi`/`svc data`
  do not touch the path the app uses, so the recovery path has never been observed failing.
- A confined seat's `htop` sees only its own sandbox's processes, by design. That is what
  the host shell is for.
- The jobs seat's "a job finished while you were elsewhere" dot is **in memory**: restarting
  the app clears it, and a job that settled while the app was closed is not re-announced — a
  session's first observation never marks it, which is the rule that stops a session switch
  from lighting a dot belonging to another session's job.
- `session/selectModel` moves the host's *global* default model, not just the session's,
  so a model picked in one client changes every session's.
