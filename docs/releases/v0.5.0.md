# DSH for Android v0.5.0

Five fixes and a new tab, most of which exist because the app was lying about one thing
or another, and one of which found a bug that had been there all along.

## The app stops guessing what is running

Subagent running state had four independent writers, two of which could only ever write
`false` — so a parent's three live children appeared, then vanished 105 ms later, while the
tree still held them. There is one authority now, and a roster pull is a *cut* that a live
frame can only outrank if it is not older than the cut. A spawned child also reaches the app
immediately rather than at the next pull, which on an idle parent could be minutes.

The host reports a subagent as running only while it is *attached*; the `active` field that
looks like liveness is a journal fold that a killed turn leaves set forever. Reading it as
liveness would have painted dead children as permanently running — worse than the bug — so it
is diagnosis only.

## Jobs come back, and their output is readable

Background jobs had not stopped working; the roster had left `session/control` for a namespace
of its own, so the app was waiting for a frame that no longer existed and nothing errored. The
seat, the sheet and the live output are back, the panel scrolls, and a live job's tail follows
while you are at the bottom and stops the moment you scroll up to read something older.

## The model list follows the desktop, and says what it means

Ordering now matches the web exactly — the signed-in account, then the official provider, then
the catalog's own order. The chip is built from the session's own selection rather than the
host's global default, is corrected when the host refuses a pick, and no longer carries one
session's model into another. It states what it is doing: `next turn`, `applying…`,
`when created`, `unavailable`.

## The Router tab

Rename and feature in one. When the session's route is local it shows the endpoint, protocol,
context window, modalities and credential state — and **real** load and prefill, read from the
router itself: the resident model, per-slot `is_processing`, prompt tokens processed against
total, cached, decoded and remaining.

It reads through a **terminal on the host**, using the namespace the Shell tab already drives,
and travels the connection the app already has. No plugin, no tunnel, no new port, no LAN
exposure, and nothing to configure on the host. Latency was the one thing that had to be
measured: 24 ms for `/props` and the model listing in a single write, 42 ms with slots, against
one 46 ms attach that is then reused.

What it will not do is invent a number. A slot read that was not asked for is labelled as not
asked rather than as an empty router, a readout that failed is distinguished from one that is
not offered, and a failed readout never turns reachability into unreachability.

## A drag on the terminal no longer opens the keyboard

Compose's `clickable` has **no movement test**: it cancels a tap only on going out of bounds or
on consumption, so a finger dragged across the grid and released inside it fired. Invisible on
every other surface here, because they are either smaller than touch slop or inside something
scrollable — the terminal grid is neither. The grid's own handler now claims a one-finger
gesture once it passes `touchSlop`, and the shared button behaviour is untouched.

## Smaller things

The composer's state caption sits under the model name instead of beside it, and the send
button is structurally impossible to push off the screen — the trailing group is the row's only
weighted child, with the ring and send measured before the chip. The terminal's cell is 10sp by
default rather than 12 (64 columns on a 320dp screen, was 53), and two fingers change it between
7 and 20 with `A−`/`A+` in the bar.

## Tests

570 across 58 suites, all passing. Worth saying plainly: four assertions in this work turned out
to be **incapable of failing** — an absolute height a stub-metric single line already satisfied,
a scroll-position test that parked at the top where a reset also lands, bounds comparisons that
would have passed against the broken row, and a wrap check asserting something this harness
cannot see at all. They are replaced or labelled, and the rule is recorded: assert a line count
or a relationship between two measured nodes, never an absolute height.
