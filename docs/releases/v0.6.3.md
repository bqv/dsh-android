# DSH for Android v0.6.3

Files becomes a place you can actually look around, a document renders as a document, and the
automation plugin the host was using has been replaced underneath us.

## Files, as a file explorer

The Files surface was derived **entirely from the session's own activity** — what it read, wrote,
edited or presented. So on a real session it showed a handful of rows, which read as a broken file
list rather than a scoped one.

It is now an explorer over the workspace, rooted at the session's working directory, with the
session's own state layered on as marks. A mark means the session read, wrote, edited or presented
that exact path; **a file with no mark has simply not been touched by this session**, which is a
fact the panel now states in words rather than leaving to inference. Two spellings of one file
merge into one mark.

Three decisions worth recording. Nothing is offered **above the root**, because the host refuses
it — no parent crumb rather than a crumb that fails. Hidden files sit behind the existing toggle,
**except a hidden file the session touched**, because the toggle governs discovery and a mark is
the session's own record. And there is no hand-maintained noise list for `node_modules/`: a dot
prefix is the one rule the host and the web already share, and a curated deny-list would be policy
invented on top of it.

The old derived list survives as **This session**, unchanged, so "what have I touched" and "what is
in this directory" both still have answers. A plain open lands on Browse; a card that names a file
lands on This session.

## Documents rendered, and the raw text still there

Markdown renders, and code is syntax-highlighted. The app already had both renderers — hand-rolled
for the chat transcript — so this is wiring rather than a new engine, and **no dependency was added
or could have been**: the offline cache carries 113 package groups and not one Markdown or
highlighting library.

The honesty rules are the interesting part. **Nothing is dropped; only interpretation is declined** —
footnote markers, raw HTML, reference links, setext headings and deep nesting all survive as literal
characters, and `.mdx` is deliberately *not* rendered, because Markdown-plus-JSX shown as prose would
be a claim the file does not support. Colouring applies only when the extension names a known
language and the file is not Markdown, so a `.log` is never falsely coloured as code. The raw source
is one tap away behind a **Source/Rendered** toggle, the language chip always states what the panel
took the file for, and the truncation banner sits above the rendering too — a rendered first 2000
lines reads "Showing 3 of 5000 lines", never as the whole document. The highlighter has no
cross-line state, so a block comment spanning lines is coloured on neither: that costs colour, never
content, and a test asserts character-for-character preservation.

## Downloading a file

Presented files, and any file in the preview, can now be saved to the phone. The bytes are paged out
of the host in 2 MiB windows and **every part is reassembled, not just the first** — the same body
carries the payload and an RPC envelope that *names* it, so a reassembly that took every part would
append JSON to the reader's file. Past the host's own 32 MiB ceiling the download **refuses and
quotes the size** rather than saving something truncated, and the bytes are fetched **before** the
save dialog opens, so a failure never leaves a half-written file under a name the reader chose.
Progress and cancellation between windows, and a failure says why on both surfaces.

## Automations: the plugin was replaced

The host's automation plugin was not renamed — `@michengai/dsh-automation` was **rejected as
incompatible** with dsh 0.2.0-rc.2 and replaced by the official Schedule bundle. The old plugin gave
every run its own throwaway session named `dsh-automation-session-…`; the new one stores a task
against the **original session** and delivers each occurrence into it.

So the app's central assumption died quietly: it identified automation sessions **by an id prefix**,
and after the swap that prefix matched **0 of 485 sessions**. Nothing errored — the landing filter,
the drawer section and the idle-alert mute simply stopped applying, and the bug they were written
for came back looking like a new one.

Sessions are now identified from the host's own `schedule/catalog` — the same snapshot the web
client marks rows from — and the change is more than a re-key. The session keeps its Workspace and
gets a clock mark instead of being lifted into a synthetic section, because a session a schedule
delivers into is now a **standing** session rather than a disposable artifact: it is preferred
against when choosing what a fresh open lands on, never hidden, and still opens when nothing else
has content. Keying on the host's `[task] …` titles was rejected — those are a human naming
convention, not something the subsystem provides.

And because an indicator that goes quiet should say why, a lost schedule signal now logs under
`DshSchedule`: the first loss of an episode, then silence until a read succeeds, so a permanent
failure cannot flood logcat. A renamed method and an answer this build cannot read are worded
differently, and a legitimately empty catalog is not a loss at all.

## Smaller things

The stats row's two chips are now each anchored to their own end of the card, so the token strip
stays on the right instead of sliding left when the counts chip has nothing to show. A **`present`
declaration is now a row in the Files list**, and a focus the list cannot hold opens anyway — a
presented card's file used to have no entry and no way to open, in 74% of measured cases. And a mass
of "unresolved reference" errors is recorded in the handoff as **stale incremental state rather
than a broken tree**, because it cost three wrong diagnoses in one afternoon.
