# DSH for Android v0.6.2

One bug, and it was two bugs. Both were about the app not asking the host a question it had
already answered once.

## A reconnect never tested the route

`attemptConnect` dialled `baseUrl()`, which read the **cached** resolution — and that cache
honours no expiry by design. Only a resume, a config change and a network callback ever
re-resolved. So once the LAN door had been passed over even once, *every* subsequent dial
redialled the cached public address without asking either door again. Nothing brought it back
short of a network edge or restarting the app, which is exactly what "LAN got stuck again"
was.

Every dial now forces a LAN-first probe — a user reconnect, an automatic retry, an auth-healed
retry, a fresh open and a setup save — before the cookie, the multiplexer and the socket.

## A transient host restart was a life sentence

`rpcRaw` treated **any** body that was not a DSH envelope as a structural verdict on the door,
which is never forgiven without a network change. But the host produces such bodies on
perfectly transient surfaces: the auth proxy answers `502 bad gateway` as plain text while the
carrier restarts, and the webserver answers `404 not found` for an endpoint it does not serve.
This box's harness restarts often, so every restart was a chance for the LAN door to be set
aside until the network changed.

The verdict now depends on the status: a **2xx** that is not an envelope is a verdict on the
door — that is the captive-portal shape the rule exists for — while **4xx/5xx** is a transport
fault, held on a growing pause and forgiven by the clock. The gate's own login refusal could
never cause this either way: it answers `401 unauthorized` with JSON, and that is handled
before the body is parsed.

## And there is finally a way to ask

The About page's LAN-door note gained **"Try the LAN door again"**. It was needed because
`connect()` had **no UI caller at all** — there was literally no way for a person to say "try
now", which is stronger evidence than a clock. Automatic retries still keep every hold, so a
captive portal costs one failed attempt per human request rather than one per retry.

The page also now distinguishes **"no LAN address is set"** from "the LAN door failed" — a
missing setting and a broken door are different facts, and they used to look the same.

## For the next time

Route decisions now log under a `DshRoute` tag: route moves, and every fault recorded against a
door. The resolver previously logged **nothing**, which is why yesterday's logcat could not
distinguish a probe that missed from a door that had been quarantined — the two are fixed by
different code and looked identical from outside.
